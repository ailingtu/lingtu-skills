# 灵途 AI 带货视频发布接口文档

> 文档版本：1.0  
> 对应技能版本：`lingtu-video-publish 0.2.0`  
> 更新时间：2026-07-29  
> 适用范围：TikTok Shop 带货视频、TikTok Shop 带货图文，以及发布流程依赖的达人、商品和文件上传接口。

## 1. 接入概览

### 1.1 服务地址

生产环境默认地址：

```text
https://api.ailingtu.com
```

客户端可通过环境变量覆盖：

```bash
export LINGTU_AI_BASE_URL=https://api.ailingtu.com
```

下文中的 `{BASE_URL}` 均指该服务地址。

### 1.2 认证方式

除对象存储的预签名上传地址外，所有灵途 API 请求都需要携带：

```http
x-api-key: <LINGTU_API_KEY>
```

JSON 请求还应携带：

```http
Accept: application/json
Content-Type: application/json
```

示例：

```bash
export LINGTU_API_KEY="<your-api-key>"

curl -X GET \
  "https://api.ailingtu.com/v1/creatorAccount/pageList?pageSize=20&pageNumber=1&valid=true" \
  -H "Accept: application/json" \
  -H "x-api-key: ${LINGTU_API_KEY}"
```

API Key 属于敏感凭证，不应写入代码仓库、日志、排期表或前端代码。

### 1.3 公共响应结构

灵途 API 使用统一 JSON envelope：

```json
{
  "code": 0,
  "data": {},
  "message": "success"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | number | `0` 表示业务成功；非 `0` 表示业务失败 |
| `data` | object | 成功响应数据，不同接口结构不同 |
| `message` | string | 提示或错误信息；服务端可能省略成功提示 |

调用方必须同时处理：

- HTTP 状态码非 2xx；
- 响应不是合法 JSON；
- HTTP 成功但 `code != 0`；
- HTTP 和业务均成功但缺少必要的 `data` 字段。

### 1.4 接口清单

| 顺序 | 方法 | 路径 | 用途 |
|---:|---|---|---|
| 1 | GET | `/v1/creatorAccount/pageList` | 查询已授权达人及其发布权限 |
| 2 | GET | `/v1/creator/tiktokshop/product/listByShop` | 查询 TikTok Shop 店铺商品 |
| 2 | GET | `/v1/creator/tiktokshop/product/listByShowcase` | 查询达人橱窗商品 |
| 3 | POST | `/v1/file/presign` | 获取媒体文件预签名上传地址 |
| 4 | PUT | `{uploadUrl}` | 向对象存储上传文件 |
| 5 | POST | `/v1/file/confirm` | 确认新文件上传完成 |
| 6 | POST | `/v1/creator/post/create` | 创建视频或图文发布任务 |

> 注意：当前客户端实际使用的商品接口路径包含 `tiktokshop`。不要使用旧路径 `/v1/creator/tiktok/product/...`。

## 2. 完整发布流程

### 2.1 带货视频

```text
查询 TikTok Shop 授权达人
  → 使用账号表 id 查询店铺或橱窗商品
  → 为视频申请预签名上传地址
  → isNew=true 时 PUT 上传并 confirm
  → 使用 fileId、creatorId 和商品信息创建 VIDEO 发布任务
  → 保存 postId 和 status
```

### 2.2 带货图文

```text
查询有图文带货权限的 TikTok Shop 达人
  → 查询店铺或橱窗商品
  → 按用户指定顺序逐张上传图片
  → 收集全部图片 fileId
  → 使用首图 fileId + 全部 fileId + 单个商品创建 PHOTO 发布任务
  → 保存 postId 和 status
```

### 2.3 两类账号标识

达人接口会同时返回 `id` 和 `creatorId`，两者不可混用：

| 字段 | 示例 | 使用位置 |
|---|---|---|
| `id` | `12345` | 商品查询接口的 Query 参数 `id` |
| `creatorId` | `2077242233106595840` | 创建发布任务时的 Body 字段 `creatorId` |

## 3. 查询已授权达人

### 3.1 接口

```http
GET /v1/creatorAccount/pageList
```

### 3.2 Query 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|---|---|
| `pageSize` | number | 是 | - | 每页数量；当前客户端通常传 `200` |
| `pageNumber` | number | 是 | - | 页码，从 `1` 开始 |
| `valid` | boolean | 否 | `true` | 是否只查询有效授权 |
| `authSource` | string | 否 | - | 授权来源，见下表 |
| `usernames` | string[] | 否 | - | 按用户名批量筛选；重复 Query 参数传递 |
| `selectionRegion` | string | 否 | - | TikTok Shop 带货达人目标地区，例如 `US` |
| `hasPhotoPermission` | boolean | 否 | - | `true` 时仅查询具有带货图文权限的账号 |

常用 `authSource`：

| 场景 | `authSource` |
|---|---|
| TikTok Shop 带货发布 | `TIKTOK_SHOP_CREATOR` |
| 普通 TikTok 视频发布 | `TIKTOK_LOGIN_KIT` |

### 3.3 请求示例

查询美国 TikTok Shop 带货达人：

```bash
curl -G \
  "https://api.ailingtu.com/v1/creatorAccount/pageList" \
  -H "Accept: application/json" \
  -H "x-api-key: ${LINGTU_API_KEY}" \
  --data-urlencode "pageSize=200" \
  --data-urlencode "pageNumber=1" \
  --data-urlencode "valid=true" \
  --data-urlencode "authSource=TIKTOK_SHOP_CREATOR" \
  --data-urlencode "selectionRegion=US"
```

仅查询可发布带货图文的达人：

```bash
curl -G \
  "https://api.ailingtu.com/v1/creatorAccount/pageList" \
  -H "Accept: application/json" \
  -H "x-api-key: ${LINGTU_API_KEY}" \
  --data-urlencode "pageSize=200" \
  --data-urlencode "pageNumber=1" \
  --data-urlencode "valid=true" \
  --data-urlencode "authSource=TIKTOK_SHOP_CREATOR" \
  --data-urlencode "selectionRegion=US" \
  --data-urlencode "hasPhotoPermission=true"
```

按多个用户名筛选时，使用重复参数：

```text
usernames=creator_a&usernames=creator_b
```

### 3.4 成功响应示例

```json
{
  "code": 0,
  "data": {
    "list": [
      {
        "id": 12345,
        "creatorId": "2077242233106595840",
        "username": "shop_creator",
        "authSource": "TIKTOK_SHOP_CREATOR",
        "oauthRegion": "USA",
        "registerRegion": "US",
        "selectionRegion": "US",
        "targetMarket": "US",
        "valid": true,
        "tagNames": ["top-tier"],
        "permissions": [
          "VIDEO_SHOPPABLE_PERMISSION",
          "PHOTO_SHOPPABLE_PERMISSION_PRODUCT"
        ]
      }
    ],
    "total": 1,
    "pageNumber": 1,
    "pageSize": 200,
    "totalPages": 1
  }
}
```

### 3.5 关键响应字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `data.list[].id` | number | 账号表主键，用于商品查询 |
| `data.list[].creatorId` | string | 达人业务 ID，用于创建发布任务 |
| `data.list[].username` | string | TikTok 用户名 |
| `data.list[].authSource` | string | 授权来源 |
| `data.list[].valid` | boolean | 授权是否有效 |
| `data.list[].permissions` | string[] | 权限码列表 |
| `data.list[].oauthRegion` | string | OAuth 授权地区 |
| `data.list[].registerRegion` | string | 注册地区 |
| `data.list[].selectionRegion` | string | 选择或目标地区 |
| `data.list[].targetMarket` | string | 目标市场；后端版本可能不返回 |

带货图文发布前应确认：

1. `authSource` 来自 TikTok Shop；
2. `permissions` 包含 `PHOTO_SHOPPABLE_PERMISSION_PRODUCT`。

地区字段随后端版本可能不同。需要推断目标市场时，建议优先读取：

```text
targetRegion → targetMarket → marketRegion → shopRegion → selectionRegion
```

上述字段均为空时，再回退到：

```text
oauthRegion → registerRegion
```

## 6. 获取预签名上传地址

### 6.1 接口

```http
POST /v1/file/presign
```

### 6.2 Request Body

```json
{
  "fileName": "video.mp4",
  "contentType": "video/mp4",
  "size": 12345678,
  "hash": "3786a02b..."
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `fileName` | string | 是 | 含扩展名的文件名 |
| `contentType` | string | 是 | MIME 类型，例如 `video/mp4`、`image/jpeg` |
| `size` | number | 是 | 文件字节数 |
| `hash` | string | 是 | 按下述兼容算法计算的内容 Hash |

### 6.3 Hash 计算规则

当前服务端兼容算法不是常规的 `SHA-256(raw bytes)`，而是：

```text
raw file bytes
  → 转为小写十六进制字符串
  → 使用 UTF-8 编码
  → 计算 SHA-256
  → 输出小写十六进制摘要
```

Python 示例：

```python
import hashlib
from pathlib import Path

raw = Path("video.mp4").read_bytes()
content_hash = hashlib.sha256(raw.hex().encode("utf-8")).hexdigest()
print(content_hash)
```

### 6.4 cURL 请求示例

假设已提前得到文件大小和兼容 Hash：

```bash
curl -X POST \
  "https://api.ailingtu.com/v1/file/presign" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ${LINGTU_API_KEY}" \
  --data '{
    "fileName": "video.mp4",
    "contentType": "video/mp4",
    "size": 12345678,
    "hash": "3786a02b..."
  }'
```

### 6.5 成功响应示例

```json
{
  "code": 0,
  "data": {
    "fileId": 591,
    "uploadUrl": "https://object-storage.example.com/presigned-url",
    "url": "https://cdn.ailingtu.com/media/video.mp4",
    "isNew": true,
    "expiresAt": "2026-07-29T12:00:00Z"
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `fileId` | number/string | 文件 ID，创建发布任务时作为 `businessId` 使用 |
| `uploadUrl` | string | 对象存储预签名 PUT 地址 |
| `url` | string | 文件最终访问地址 |
| `isNew` | boolean | `true` 表示需要上传；`false` 表示文件已存在，可秒传 |
| `expiresAt` | string | 预签名地址失效时间 |

兼容处理建议：

- 文件 ID 优先读取 `data.fileId`，旧响应可回退读取 `data.id`；
- `isNew=false` 时跳过 PUT 和 confirm；
- `isNew=true` 时必须执行 PUT，成功后再 confirm；
- 旧响应缺少 `isNew` 但存在 `uploadUrl` 时，按新文件处理。

## 7. 上传文件到预签名地址

### 7.1 接口

```http
PUT {uploadUrl}
```

该请求直接发往对象存储，不使用 `{BASE_URL}`，也不要携带 `x-api-key`。

请求头：

```http
Content-Type: <与 presign 请求一致的 MIME 类型>
```

请求体为文件原始字节。

### 7.2 cURL 示例

```bash
curl -X PUT \
  "<uploadUrl>" \
  -H "Content-Type: video/mp4" \
  --upload-file "./video.mp4"
```

判断规则：

- HTTP 状态码小于 `400`：上传成功；
- HTTP 状态码大于或等于 `400`：上传失败，不应调用 confirm 或创建发布任务。

预签名地址通常有有效期。地址失效后应重新调用 `/v1/file/presign`。

## 8. 确认文件上传完成

### 8.1 接口

```http
POST /v1/file/confirm
```

仅新文件完成 PUT 后需要调用。秒传文件不需要调用。

### 8.2 Request Body

```json
{
  "fileId": 591
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `fileId` | number/string | 是 | `/v1/file/presign` 返回的文件 ID |

### 8.3 请求示例

```bash
curl -X POST \
  "https://api.ailingtu.com/v1/file/confirm" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ${LINGTU_API_KEY}" \
  --data '{"fileId":591}'
```

确认成功后，才可将该 `fileId` 用于创建发布任务。

## 9. 创建发布任务

### 9.1 接口

```http
POST /v1/creator/post/create
```

该接口同时支持：

- TikTok Shop 带货视频：`platform=TIKTOK_SHOP`、`mediaType=VIDEO`；
- TikTok Shop 带货图文：`platform=TIKTOK_SHOP`、`mediaType=PHOTO`；
- 普通 TikTok 视频：`platform=TIKTOK`、`mediaType=VIDEO`。

本节重点说明前两种带货发布方式。

### 9.2 公共字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `businessId` | string | 是 | 视频 fileId；图文时为首图 fileId |
| `businessType` | string | 是 | 当前上传文件使用 `FILE`；AI 任务可使用 `AI_TASK` |
| `creatorId` | string | 是 | 达人接口返回的 `creatorId` |
| `title` | string | 是 | 视频文案或图文 Caption |
| `platform` | string | 是 | `TIKTOK_SHOP` 或 `TIKTOK` |
| `mediaType` | string | 是 | `VIDEO` 或 `PHOTO`；客户端应明确传递 |
| `scheduledAt` | number | 否 | 定时发布时间，Unix Epoch 毫秒 |
| `scheduledTz` | string | 否 | IANA 时区，例如 `America/New_York` |
| `oauthRegion` | string | 否 | 达人 OAuth 授权地区 |
| `tiktokShop` | object | 条件必填 | TikTok Shop 带货视频参数 |
| `tiktokShopPhoto` | object | 条件必填 | TikTok Shop 带货图文参数 |
| `tiktok` | object | 条件必填 | 普通 TikTok 视频参数 |

定时发布建议同时传 `scheduledAt` 和 `scheduledTz`。例如：

```json
{
  "scheduledAt": 1784896665989,
  "scheduledTz": "America/New_York"
}
```

## 11. 创建 TikTok Shop 带货图文

### 11.1 业务约束

当前支持“多图 + 单个商品锚点”：

- `postType` 固定为 `MULTI_PHOTO_ONE_ANCHOR`；
- 一条内容允许 1～15 张图片；
- 所有图片共用一个商品；
- `productLinks` 长度必须为 `1`；
- `businessId` 必须等于首图的 fileId；
- `businessIds` 必须包含全部图片 fileId，并严格保持用户指定的图片顺序。

### 11.2 Request Body

```json
{
  "businessId": "591",
  "businessType": "FILE",
  "creatorId": "2077242233106595840",
  "title": "Summer Sale 2026 #summer",
  "platform": "TIKTOK_SHOP",
  "mediaType": "PHOTO",
  "scheduledAt": 1784896665989,
  "scheduledTz": "America/New_York",
  "oauthRegion": "USA",
  "tiktokShopPhoto": {
    "postType": "MULTI_PHOTO_ONE_ANCHOR",
    "businessIds": ["591", "592"],
    "productLinks": [
      {
        "productId": "1732280564607717841",
        "title": "Summer Vibes Cord",
        "source": "SHOP"
      }
    ],
    "musicInfo": {
      "id": "7567668059796720391",
      "title": "original sound",
      "author": "Ivan",
      "duration": "15"
    }
  }
}
```

### 11.3 `tiktokShopPhoto` 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `postType` | string | 是 | 固定 `MULTI_PHOTO_ONE_ANCHOR` |
| `businessIds` | string[] | 是 | 全部图片 fileId，顺序与用户指定顺序一致 |
| `productLinks` | object[] | 是 | 长度必须为 `1` |
| `musicInfo` | object | 否 | 背景音乐信息；不需要音乐时整个字段不传 |

`productLinks[]`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `productId` | string | 是 | 商品 ID |

## 12. 创建发布任务响应

### 12.1 成功响应示例

```json
{
  "code": 0,
  "data": {
    "id": 100,
    "postId": "post_xxx",
    "platform": "TIKTOK_SHOP",
    "title": "Summer Sale 2026 #summer",
    "videoUrl": "https://cdn.ailingtu.com/media/video.mp4",
    "status": "SCHEDULED"
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `data.id` | number/string | 灵途发布记录 ID |
| `data.postId` | string | 平台发布任务 ID，应持久化保存 |
| `data.platform` | string | 发布平台 |
| `data.title` | string | 发布文案 |
| `data.videoUrl` | string | 媒体地址；图文或部分状态下可能为空 |
| `data.status` | string | 发布任务状态，例如 `SCHEDULED` |

创建接口成功表示发布任务已被服务端接收，不应等同于 TikTok 最终发布成功。调用方应保存 `postId` 和 `status`，并在发布记录中继续确认最终状态：

```text
https://app.ailingtu.com/video-center?tab=records
```

## 13. 客户端校验规则

### 13.1 视频文案

| 项目 | 规则 |
|---|---|
| 最大长度 | 4000 字符 |
| Hashtag | 支持 `#` |
| 其他字符 | 当前发布客户端会清理不支持的表情、标点或特殊符号 |
| 空文案 | 当前客户端会回退为 `Untitled`，业务接入建议要求用户明确填写 |

### 13.2 购物车标题

| 项目 | 规则 |
|---|---|
| 最大长度 | 30 字符 |
| 字符要求 | 当前发布客户端会清理不支持的表情、标点或特殊符号 |
| 来源 | 可由商品接口的商品标题生成，也可由用户填写 |

### 13.3 带货图文图片

| 项目 | 规则 |
|---|---|
| 图片数量 | 1～15 张 |
| 单张大小 | 不超过 10 MB |
| 格式 | JPG、JPEG、PNG、WEBP、HEIC、BMP |
| 宽高比 | `w/h ∈ [9/16, 16/9]`，包含边界 |
| 上传顺序 | 必须与最终展示顺序一致 |

### 13.4 平台与媒体类型组合

| `platform` | `mediaType` | 是否支持 | 说明 |
|---|---|---:|---|
| `TIKTOK_SHOP` | `VIDEO` | 是 | TikTok Shop 带货视频 |
| `TIKTOK_SHOP` | `PHOTO` | 是 | TikTok Shop 带货图文 |
| `TIKTOK` | `VIDEO` | 是 | 普通 TikTok 视频 |
| `TIKTOK` | `PHOTO` | 否 | 带货图文仅支持 TikTok Shop |

## 14. 错误处理

### 14.1 HTTP 错误

收到非 2xx 状态码时，应记录：

- 请求方法和路径；
- HTTP 状态码；
- 服务端响应中的 `message`；
- 本地请求追踪 ID（如调用方有生成）。

不得在日志中记录完整 `x-api-key` 或预签名 URL。

### 14.2 业务错误

HTTP 2xx 但 `code != 0` 时，应视为失败：

```json
{
  "code": 10001,
  "message": "creator account is invalid",
  "data": null
}
```

建议展示 `message`，并保留 `code` 供排查。

### 14.3 常见失败场景

| 场景 | 建议处理 |
|---|---|
| 未找到达人 | 确认用户名及授权状态，重新查询达人列表 |
| 达人授权失效 | 引导重新授权后再发布 |
| 图文权限不足 | 确认 `PHOTO_SHOPPABLE_PERMISSION_PRODUCT` |
| 商品列表为空 | 确认 TikTok Shop 店铺已绑定且账号匹配 |
| 商品查询失败 | 检查是否误把 `creatorId` 当作 Query 参数 `id` |
| 预签名过期 | 重新调用 `/v1/file/presign` |
| PUT 上传失败 | 不调用 confirm；重新申请地址后重试 |
| confirm 失败 | 不创建发布任务；确认文件状态后重试 |
| 缺少 `fileId` | 终止当前条目，不创建发布任务 |
| 图文多于一个商品 | 拒绝请求；当前仅支持单商品锚点 |
| `businessId` 不是首图 | 在客户端修正为 `businessIds[0]` |
| 定时时区不明确 | 使用 IANA 时区并重新计算毫秒时间戳 |

### 14.4 重试建议

- 网络超时、HTTP `408`、`429`、`5xx` 可采用指数退避重试；
- 参数错误、权限错误、授权失效等业务错误不应盲目重试；
- PUT 重试前应确认预签名地址仍在有效期内；
- 创建发布任务超时后，不应立即无条件重复创建，以免生成重复发布任务；应先通过发布记录确认是否已经创建成功。

## 15. 联调检查清单

发布前：

- [ ] `LINGTU_API_KEY` 有效且未暴露在客户端日志中；
- [ ] 达人 `valid=true`；
- [ ] 已区分账号表 `id` 与发布用 `creatorId`；
- [ ] 带货图文达人具备图文发布权限；
- [ ] 商品 ID、标题和来源匹配；
- [ ] 文案和购物车标题符合长度及字符限制；
- [ ] 定时时间已按 `scheduledTz` 转换为 Epoch 毫秒；
- [ ] 图片数量、大小、格式和宽高比均合规。

上传阶段：

- [ ] Hash 使用“原始字节转 hex 后再 SHA-256”的兼容算法；
- [ ] `isNew=false` 时跳过 PUT 和 confirm；
- [ ] `isNew=true` 时 PUT 使用与 presign 一致的 `Content-Type`；
- [ ] PUT 成功后已调用 confirm；
- [ ] 每个媒体文件均取得非空 `fileId`。

创建任务：

- [ ] 视频请求明确传 `mediaType=VIDEO`；
- [ ] 图文请求明确传 `mediaType=PHOTO`；
- [ ] 图文 `businessId == businessIds[0]`；
- [ ] 图文 `businessIds` 顺序正确；
- [ ] 图文 `productLinks` 长度为 `1`；
- [ ] 已保存响应中的 `postId` 和 `status`；
- [ ] 已在发布记录页确认最终发布结果。

## 16. 最小端到端示例


```json
  "id": 12345,
  "creatorId": "2077242233106595840",
  "username": "shop_creator"
}
```

```http
GET /v1/creator/tiktokshop/product/listByShop
  ?id=12345
  &origin=TIKTOK
  &pageSize=20
```

得到：

```json
{
  "id": "1732280564607717841",
  "title": "Summer Vibes Cord"
```

