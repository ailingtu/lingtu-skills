# 交付约定

## 方案阶段

简洁交付：

1. 一句话改编方向。
2. 参考笔记的内容结构与视觉语法摘要。
3. 素材可用情况和缺口。
4. 逐页映射表。
5. 需要用户决定的真实分歧；没有则直接等待确认或按“直接生成”继续。

不要把内部完整提示词、接口响应和长篇素材描述全部倾倒给用户。用户索取时再提供。

## 成品阶段

按顺序给出：

- 每个可直接复制的 `outputDir/YYYY-MM-DD-系列名-NN/` 绝对路径；如果用户指定了输出目录，说明是否直接采用或因冲突使用了下一个编号。
- 每个交付目录中的 JPG 成品图片和 `发布计划.md`。
- 一个推荐标题及两个备选标题。
- 正文和相关标签。
- 可选评论区引导语。
- 简短验收结论：成功页数、重试页面、仍存在的问题。
- AI 补充场景和未确认事实说明。

同一版本的所有可发布文件必须集中在一个独立成品目录，不要求用户再从工作档案、草稿或其他版本中收集文件。该目录只能包含按页序编号的 JPG 和一份 `发布计划.md`，确保可以整目录复制给素人。`发布计划.md` 至少包含图片顺序、推荐标题、两个备选标题、正文、标签、可选评论区引导和必要的发布注意事项。

`assets-analysis.json`、`report.json`、参考图、提示词、草稿和接口响应均属于内部工作档案，不得写入 `outputDir`。每个版本的 `report.json` 至少记录：taskId、outputDir、workDir、工作版本目录、交付目录、参考链接、参考图片路径、素材清单路径、每页提示词路径、参考角色顺序、scheduleId、最终结果路径、重试次数和验收状态。未知字段写 `null` 并说明原因，不猜测。不要记录 API Key。

默认只向用户展示和链接交付目录，不把内部工作目录列为交付物。用户明确要求不保留工作文件时，在确认所有成品通过验收后清理精确的临时 `workDir`，并说明工作文件已不再保留、后续修改可能需要重新分析或生成。

不自动发布，不把生成完成表述为已经发布或获得流量。
