# 交付约定

## 方案阶段

简洁交付：

1. 一句话改编方向。
2. 参考笔记的内容结构与视觉语法摘要。
3. 素材可用情况和缺口。
4. 逐页映射表。
5. 需要用户决定的真实分歧；没有则直接等待确认或按“直接生成”继续。

不要把内部完整提示词、接口响应和长篇素材描述全部倾倒给用户。用户索取时再提供。

## 成品阶段

按顺序给出：

- 实际任务根目录和版本目录的绝对路径；如果用户指定了输出目录，说明是否直接采用或因冲突建立了子目录。
- 每个版本 `final/` 中所有 JPG 成品图片和 `发布要求.md` 的绝对路径。
- 一个推荐标题及两个备选标题。
- 正文和相关标签。
- 可选评论区引导语。
- 简短验收结论：成功页数、重试页面、仍存在的问题。
- AI 补充场景和未确认事实说明。

同一版本的所有可发布文件必须集中在一个 `final/`，不要求用户再从 `drafts/`、任务根目录或其他版本中收集文件。`发布要求.md` 至少包含图片顺序、推荐标题、两个备选标题、正文、标签、可选评论区引导和必要的发布注意事项。

每个版本的 `report.json` 至少记录：任务根目录、版本目录、参考链接、参考图片路径、素材清单路径、每页提示词路径、参考角色顺序、scheduleId、最终结果路径、重试次数和验收状态。未知字段写 `null` 并说明原因，不猜测。不要记录 API Key。

不自动发布，不把生成完成表述为已经发布或获得流量。
